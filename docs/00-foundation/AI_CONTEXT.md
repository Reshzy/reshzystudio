# Design Philosophy

The artwork is always the hero.

The interface exists only to enhance the artwork.

Nothing should visually compete with the work itself.

The website should feel like walking through a contemporary art museum.

Less is more.

Whitespace is intentional.

Typography creates hierarchy.

Motion creates rhythm.

The interface should disappear.

The experience should remain.

# Things To Avoid

Do not introduce:

• Glassmorphism

• Heavy gradients

• Neon aesthetics

• Gaming-inspired UI

• Dashboard layouts

• Generic portfolio templates

• Material Design appearance

• Bootstrap aesthetics

• Excessive decoration

• Random animations

• Overuse of shadows

Everything should feel intentional.

---

# Technical Philosophy

Prioritize:

Maintainability

Performance

Accessibility

Scalability

Consistency

Readability

Every component should have a single responsibility.

Avoid unnecessary abstraction.

Prefer composition over complexity.

Keep the architecture clean.

---

# Motion Philosophy

Animations should explain.

Not entertain.

Motion exists to:

Guide attention

Reveal information

Connect sections

Provide continuity

Improve spatial awareness

Never animate simply because something can move.

Every animation must have purpose.

---

# Typography Philosophy

Typography is one of the most important design elements.

Large typography is encouraged.

Hierarchy should rely on:

Scale

Weight

Spacing

Alignment

Avoid relying on color alone.

Typography should create rhythm across the page.

---

# Image Philosophy

Artwork should always be displayed at high quality.

Never aggressively crop artwork.

Respect original aspect ratios whenever possible.

Image loading should feel seamless.

Avoid compression artifacts.

Gallery presentation is more important than loading dozens of images simultaneously.

---

# Component Philosophy

Components should be reusable.

Simple.

Predictable.

Composable.

Avoid deeply nested component trees.

Prefer small focused components.

---

# Accessibility

Accessibility is not optional.

Support:

Keyboard navigation

Reduced motion

Proper semantic HTML

ARIA where appropriate

Screen readers

Sufficient color contrast

Responsive layouts

Accessibility is part of good design.

---

# Performance Goals

Excellent Lighthouse scores.

Fast initial load.

Minimal layout shift.

Lazy load media.

Optimize images.

Avoid unnecessary JavaScript.

Do not sacrifice performance for decorative effects.

---

# Responsive Philosophy

Desktop is the primary experience.

Mobile is equally important.

Do not simply shrink layouts.

Redesign layouts appropriately for smaller screens.

Maintain visual elegance on every device.

---

# Code Style

Write modern TypeScript.

Prefer functional components.

Avoid duplicated logic.

Comment only when necessary.

Favor readable code over clever code.

Meaningful variable names.

Meaningful file names.

Consistent formatting.

---

# Folder Organization

Organize code by feature whenever appropriate.

Keep components close to where they are used.

Separate:

UI

Animation

Utilities

Content

Configuration

Avoid large monolithic folders.

---

# Copywriting

Writing should be:

Minimal

Thoughtful

Editorial

Human

Avoid clichés.

Avoid marketing language.

Avoid AI-sounding introductions.

The work should speak first.

---

# Decision Making

When implementing features, prioritize:

1.

User experience

2.

Design consistency

3.

Performance

4.

Accessibility

5.

Developer convenience

Never reverse this order.

# If Unsure

When making decisions:

Choose simplicity.

Choose clarity.

Choose timelessness.

Choose restraint.

Never choose complexity simply because it appears impressive.

# Definition of Success

The finished website should cause visitors to think:

"This artist has exceptional taste."

Only later should they realize:

"This artist also has exceptional technical ability."

That discovery is intentional.

The portfolio should earn admiration through experience rather than explanation.

Every pixel.

Every animation.
